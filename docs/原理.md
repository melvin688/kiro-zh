# 原理：为什么改了语言包还是英文

Kiro 的文案不是单一来源。要真正全中文，得同时处理三层。

## 1. 官方语言包（老式 NLS）

`~/.kiro/extensions/ms-ceintl.vscode-language-pack-zh-hans-*/translations/main.i18n.json` 是一个大字典：

```json
{ "contents": { "vs/base/browser/ui/actionbar/actionViewItems": { "titleLabel": "{0} ({1})" } } }
```

只有走 `localize(module, key, defaultMessage)` 的代码才会查它。装了语言包后菜单、侧边栏、大部分原生对话框变中文，靠的就是这一层。

局限：Kiro 自己新增的模块未必在语言包里；`localize(index)` 形式的代码根本不查它。

## 2. NLS 消息数组（渲染进程真正用的那张表）

`resources/app/out/nls.messages.json` 是一个 **22,000+ 条的扁平字符串数组**，`out/nls.messages.js` 把它挂到 `globalThis._VSCODE_NLS_MESSAGES`。workbench / sessions 的打包产物用 `d(15100, null)` 这种索引形式取文案，索引指向这张表。

所以：

- 改语言包 → 这些字符串不动。
- 改这张表 → 立刻生效，但还要清 `%APPDATA%/Kiro/clp`（按语言包哈希缓存的 NLS 结果），否则用的还是旧缓存。

`localize_nls.py` 的映射方式是：读 `out/nls.metadata.json` 的英文原文 + 语言包的中文，构造「英文 → 中文」字典，再按**内容**替换数组元素。同一英文有多种译法（例如 `What's new` 在不同模块译作「新增功能」「最新功能」）时取出现最多的那个。

**不要按索引写数组**：workbench 与 sessions 两个 bundle 的索引顺序不一致，按索引填会把 A 的译文写到 B 的位置上，界面出现风马牛不相及的中文。

## 3. 硬编码字面量

聊天面板是独立打包的 React 应用（`extensions/kiro.kiro-agent/packages/kiro-ui-agent-chat/dist/assets/mermaid-*.js`），权限模式、额度文案、状态栏项也都在 minified bundle 里直接写死英文，没走任何 i18n。

这类只能按字面量替换。`patch_ui.py` 收录了实测可用的替换对，替换前先判重（新串已存在就跳过），因此可以反复执行。

## 完整性校验

`resources/app/product.json` 有 `checksums` 字段，形如：

```json
{ "vs/workbench/workbench.desktop.main.js": "base64(sha256) 去掉 = 的 43 字符" }
```

改了 `out/` 下被列出的文件又不更新校验值，启动时会弹「Kiro 安装似乎损坏，请重新安装」。`fix_checksums.py` 逐条重算回填。

## 额度百分比怎么加出来的

状态栏额度文案由 `extension.js` 里的一个函数拼装（1.4.178 中是 `function Zug(e,t)`）。原逻辑只输出 `Kiro Pro 82.68 / 789` 加相对时间，补丁插入三件事：

1. `pc = round(used / limit * 100)`；
2. 用 `▰`(U+25B0) / `▱`(U+25B1) 拼 10 格进度条；
3. 输出改成 `${label} ▰▱… 10% · 82.68 / 789 更新于 刚刚`。

这段依赖具体 minified 符号，换版本大概率未命中；未命中时脚本会提示，其余汉化照常。

## 更新后怎么办

Kiro 自动更新会替换 `out/`、`extensions/kiro.kiro-agent/dist/` 与 `product.json`，补丁全部失效（`.zhbak` 也是旧版本的）。重跑 `apply.py` 即可：它会重新识别版本、重新备份、重新打补丁。
